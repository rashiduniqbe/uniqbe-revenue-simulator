# Phase 3 (FX Subsystem) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the FX rate subsystem: two rate providers (Frankfurter primary, a configurable commercial fallback), a Redis-backed store with a committed seed fallback and read-time `ageDays`/`degraded` computation, and the two API routes (`/api/fx` read, `/api/cron/fx-refresh` daily writer) that make live-but-honest-about-its-age exchange rate data available to the (not-yet-built) UI.

**Architecture:** Three small, swappable modules feed one store. `src/fx/providers/frankfurter.ts` and `src/fx/providers/fallback.ts` each fetch a rate snapshot from an HTTP source and return the same shape (`FxRawSnapshotType` — no `ageDays`/`degraded`, since those are only meaningful "as of now" and must never be cached stale). `src/fx/store.ts` is the only place that touches Redis or computes `ageDays`/`degraded`; it reads via Upstash's REST client (edge-compatible), and on a missing or unreachable key falls back to the committed `src/data/fx-seed.json`. Two Next.js Route Handlers wire it to HTTP: `GET /api/fx` (edge runtime, public, read-only) and `POST /api/cron/fx-refresh` (nodejs runtime, `CRON_SECRET`-gated, writes on success, **never** overwrites a good key on failure). The calculation engine (Phase 2, already built) never touches any of this — it receives an already-resolved `FxInput` as a plain argument, exactly as `ADR-004` requires.

**Tech Stack:** Next.js 15 Route Handlers (edge + nodejs runtimes), `@upstash/redis` (new dependency — REST-based, works on edge), Zod 3 (already installed), Vitest 2 (already installed), `tsx` (already installed, for the seed script).

**Spec:** `PROJECT_SPEC.md` (this repo) — specifically §0 (env var manifest), §4 (repo structure — `src/fx/**`), §6 (the FX subsystem contract, authoritative for this plan), ADR-003 (why Upstash Redis, the fallback chain), ADR-004 (why the engine never does its own I/O — context for why this subsystem exists at all), §14 Phase 3 tickets T-16–T-18.

## Global Constraints

- Package manager `pnpm`; Node `22.x` target.
- TypeScript strict, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true` (type-only imports use `import type`).
- `@upstash/redis` is the only Redis client (ADR-003) — no `ioredis`, no raw `redis` package. Its REST-over-HTTP design is what makes `/api/fx` able to run on the edge runtime.
- **`ageDays` and `degraded` are never stored** — only `base`, `rates`, `asOf`, `fetchedAt`, `provider` are persisted (Redis or `fx-seed.json`). Both are computed fresh every time `store.ts` reads a snapshot, from `asOf` compared against the current time. Storing them would mean serving an `ageDays` that was true at write time but wrong by the time anyone reads it.
- `degraded = (provider === "seed") || (ageDays > 3)` — a fresh, successful fallback-provider fetch is **not** degraded on its own; only actually-stale data or the last-resort seed file counts (§6.2's table ties `degraded` to age and to the seed-serving case specifically, not to which provider produced a fresh rate).
- **Never overwrite a good Redis value with a failure sentinel.** If both providers fail during the cron refresh, log the error and return without writing — the old key (however old) stays in place (§6.2, row 1).
- `/api/cron/fx-refresh` **must** reject any request without `Authorization: Bearer ${CRON_SECRET}` with a 401, and this check must run before any provider is called.
- `asOf` always comes from the **provider's** response field, never from the server clock — a Sunday fetch can legitimately return Friday's date.
- One ticket per commit, Conventional Commits format.
- Run `pnpm verify` (`typecheck && lint && test`) before considering any task done.
- Relative imports throughout (no path aliases configured in this repo — `tsconfig.json`/`vitest.config.ts` don't define any; follow the existing convention).

## Deviation from the spec's file tree (read before starting Task 1)

`PROJECT_SPEC.md` §4 lists `src/fx/types.ts` as a file holding the `FxSnapshot` type. Phase 1 already put `FxSnapshot`/`FxSnapshotType` in `src/lib/schemas.ts` instead (alongside `Catalogue`, `MarketRules`, etc. — the project's one central Zod file), and it's already committed there. This plan follows that established pattern rather than the spec's idealized tree: no `src/fx/types.ts` is created. Task 1 adds one more schema, `FxRawSnapshot`, to the same `src/lib/schemas.ts` file.

## Deviation from the spec's provider-shape assumption (read before starting Task 1)

§0's env manifest defines `FX_FALLBACK_URL`/`FX_FALLBACK_API_KEY` as optional with empty defaults — the spec never names the actual "commercial backup" service, because Uniqbe hasn't picked one yet. This plan's fallback provider (`src/fx/providers/fallback.ts`) assumes the configured backup returns a Frankfurter-compatible JSON shape (`{ date: string, rates: { GBP: number, AUD: number } }`), since that's a common, simple convention for FX APIs and keeps the provider trivially testable today. **When Uniqbe picks a real commercial provider, only this one file's response-parsing needs to change** — the function signature (`fetchFallbackSnapshot(): Promise<FxRawSnapshotType>`) and everything that calls it stay the same. If `FX_FALLBACK_URL` is unset (the default), the function throws immediately without making a network call, so the refresh cron correctly falls through to "leave the existing key untouched."

// src/fx/providers/frankfurter.ts
import { FxRawSnapshot, type FxRawSnapshotType } from "../../lib/schemas";

const DEFAULT_FRANKFURTER_URL = "https://api.frankfurter.dev/v1/latest";

type FrankfurterResponse = {
  date: string;
  rates: Record<string, number>;
};

export async function fetchFrankfurterSnapshot(
  fetchImpl: typeof fetch = fetch,
  baseUrl: string = process.env.FX_PRIMARY_URL ?? DEFAULT_FRANKFURTER_URL,
): Promise<FxRawSnapshotType> {
  const url = `${baseUrl}?from=USD&to=GBP,AUD`;
  const response = await fetchImpl(url);
  if (!response.ok) {
    throw new Error(`Frankfurter request failed: ${response.status}`);
  }
  const body = (await response.json()) as FrankfurterResponse;
  const gbp = body.rates.GBP;
  const aud = body.rates.AUD;
  if (typeof gbp !== "number" || typeof aud !== "number") {
    throw new Error("Frankfurter response missing GBP/AUD rate");
  }
  return FxRawSnapshot.parse({
    base: "USD",
    rates: { GBP: gbp, AUD: aud },
    asOf: body.date,
    fetchedAt: new Date().toISOString(),
    provider: "frankfurter",
  });
}
```

// src/fx/providers/fallback.ts
import { FxRawSnapshot, type FxRawSnapshotType } from "../../lib/schemas";

type FallbackResponse = {
  date: string;
  rates: Record<string, number>;
};

export async function fetchFallbackSnapshot(
  fetchImpl: typeof fetch = fetch,
  url: string | undefined = process.env.FX_FALLBACK_URL,
  apiKey: string | undefined = process.env.FX_FALLBACK_API_KEY,
): Promise<FxRawSnapshotType> {
  if (!url) {
    throw new Error("FX_FALLBACK_URL is not configured");
  }
  const response = await fetchImpl(url, {
    headers: apiKey ? { Authorization: `Bearer ${apiKey}` } : undefined,
  });
  if (!response.ok) {
    throw new Error(`Fallback FX request failed: ${response.status}`);
  }
  const body = (await response.json()) as FallbackResponse;
  const gbp = body.rates.GBP;
  const aud = body.rates.AUD;
  if (typeof gbp !== "number" || typeof aud !== "number") {
    throw new Error("Fallback response missing GBP/AUD rate");
  }
  return FxRawSnapshot.parse({
    base: "USD",
    rates: { GBP: gbp, AUD: aud },
    asOf: body.date,
    fetchedAt: new Date().toISOString(),
    provider: "fallback",
  });
}
```

```typescript
// src/fx/store.ts
import { Redis } from "@upstash/redis";
import fxSeedRaw from "../data/fx-seed.json";
import { FxRawSnapshot, type FxRawSnapshotType, type FxSnapshotType } from "../lib/schemas";

const FX_REDIS_KEY = "fx:snapshot";
const DEGRADED_AGE_DAYS_THRESHOLD = 3;
const MS_PER_DAY = 1000 * 60 * 60 * 24;

type RedisLike = {
  get: (key: string) => Promise<unknown>;
  set: (key: string, value: unknown) => Promise<unknown>;
};

function defaultRedisClient(): RedisLike {
  return Redis.fromEnv();
}

export function computeAgeDays(asOf: string, now: Date = new Date()): number {
  const asOfDate = new Date(`${asOf}T00:00:00.000Z`);
  const diffMs = now.getTime() - asOfDate.getTime();
  return Math.floor(diffMs / MS_PER_DAY);
}

export function toFxSnapshot(raw: FxRawSnapshotType, now: Date = new Date()): FxSnapshotType {
  const ageDays = computeAgeDays(raw.asOf, now);
  const degraded = raw.provider === "seed" || ageDays > DEGRADED_AGE_DAYS_THRESHOLD;
  return { ...raw, ageDays, degraded };
}

function seedSnapshot(now: Date): FxSnapshotType {
  return toFxSnapshot(FxRawSnapshot.parse(fxSeedRaw), now);
}

export async function readFxSnapshot(
  redis: RedisLike = defaultRedisClient(),
  now: Date = new Date(),
): Promise<FxSnapshotType> {
  try {
    const stored = await redis.get(FX_REDIS_KEY);
    if (stored === null || stored === undefined) {
      return seedSnapshot(now);
    }
    return toFxSnapshot(FxRawSnapshot.parse(stored), now);
  } catch {
    return seedSnapshot(now);
  }
}

export async function writeFxSnapshot(
  raw: FxRawSnapshotType,
  redis: RedisLike = defaultRedisClient(),
): Promise<void> {
  await redis.set(FX_REDIS_KEY, raw);
}
```

**Note on `RedisLike`:** the store depends only on `get`/`set`, not the full `@upstash/redis` `Redis` class — this is what lets tests pass a plain `{ get, set }` object instead of a real Redis connection, and keeps `store.ts` the only file that needs to know Upstash exists at all.

// scripts/seed-fx.ts
import { writeFileSync } from "node:fs";
import path from "node:path";
import { fetchFrankfurterSnapshot } from "../src/fx/providers/frankfurter";
import { FxRawSnapshot } from "../src/lib/schemas";

async function main(): Promise<void> {
  const live = await fetchFrankfurterSnapshot();
  const seed = FxRawSnapshot.parse({ ...live, provider: "seed" });
  const outPath = path.join(process.cwd(), "src/data/fx-seed.json");
  writeFileSync(outPath, `${JSON.stringify(seed, null, 2)}\n`);
  console.log(`Wrote ${outPath}: ${seed.rates.GBP} GBP, ${seed.rates.AUD} AUD, as of ${seed.asOf}`);
}

main().catch((error: unknown) => {
  console.error("seed-fx failed:", error);
  process.exit(1);
});
```

This is a developer-run maintenance script (`pnpm fx:seed`), not part of the request path — it lets whoever maintains this repo periodically refresh the committed last-resort fallback with a real, current rate. `console.log`/`console.error` here are the script's own user-facing CLI output, not debug leftovers.

// src/app/api/cron/fx-refresh/route.ts
export const runtime = "nodejs";

import { NextResponse } from "next/server";
import { fetchFrankfurterSnapshot } from "../../../../fx/providers/frankfurter";
import { fetchFallbackSnapshot } from "../../../../fx/providers/fallback";
import { writeFxSnapshot } from "../../../../fx/store";

export async function POST(request: Request): Promise<Response> {
  const cronSecret = process.env.CRON_SECRET;
  const authHeader = request.headers.get("authorization");
  if (!cronSecret || authHeader !== `Bearer ${cronSecret}`) {
    return NextResponse.json({ error: "unauthorized" }, { status: 401 });
  }

  try {
    const snapshot = await fetchFrankfurterSnapshot();
    await writeFxSnapshot(snapshot);
    return NextResponse.json({ ok: true, provider: snapshot.provider });
  } catch (primaryError: unknown) {
    try {
      const snapshot = await fetchFallbackSnapshot();
      await writeFxSnapshot(snapshot);
      return NextResponse.json({ ok: true, provider: snapshot.provider });
    } catch (fallbackError: unknown) {
      console.error("fx-refresh: both providers failed, leaving existing key untouched", {
        primaryError,
        fallbackError,
      });
      return NextResponse.json({ ok: false, error: "both providers failed" }, { status: 502 });
    }
  }
}
```

**Note on `console.error`:** this is the one place in this plan that logs to the console — it runs only in this Vercel serverless function on total provider failure, matching §6.2's explicit requirement to "emit an error-level log," and `console.error` output is exactly what Vercel's function logs dashboard captures. This isn't a debug statement left behind; it's the mechanism.
