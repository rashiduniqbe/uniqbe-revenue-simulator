# Phase 4 (UI — UK) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the UK-only simulator page: a product search, an input panel bound to the URL, a breakdown table, a verdict card with a cost waterfall, a price-suggestion control, and a full warning surface — all driven by the already-built, already-tested `calculate()`/`suggestPrice()` engine (Phase 2) and the already-built `/api/fx`-backed `FxSnapshot` (Phase 3). AU support (market switching) is explicitly Phase 5 (T-26) — this phase hardcodes UK.

**Architecture:** `src/app/page.tsx` is a Server Component that loads the three static/semi-static inputs the client never needs to fetch itself — `src/data/catalogue.json`, `src/data/market-rules.json`, and the current `FxSnapshot` (via `readFxSnapshot()`, imported directly — no HTTP round-trip to its own `/api/fx` route) — and passes them as props into `<SimulatorShell />`, the one `"use client"` component that owns all interactive state. Every piece of *decision logic* (URL encode/decode, fuzzy product search, warning copy/priority, waterfall segment geometry, FX badge text formatting) is factored into a small pure function in `src/lib/*.ts`, each with its own Vitest unit tests — this is what keeps the plan test-first without installing a component-testing stack this repo doesn't have yet (see Global Constraints). The React components themselves are thin: they call a pure function and render its result. `SimulatorShell` calls the engine's own `calculate()`/`suggestPrice()` directly — per ADR-004 the engine already runs client-side, so this is not a new architectural decision, just the first place that wiring actually happens.

**Tech Stack:** Next.js 15 App Router (Server + Client Components), React 19, `fuse.js@7` (new dependency), `nuqs@2` (new dependency), Tailwind CSS 4 (already installed), Vitest 2 (already installed, pure-logic tests only — see Global Constraints for why no component-rendering tests are in this plan).

**Spec:** `PROJECT_SPEC.md` (this repo) — specifically §4 (repo structure), §6.3 (non-negotiable FxBadge/DisclaimerBar display rules), §7 (engine contract — already built, read-only for this plan), §9 (UI specification: design tokens, wireframe, cost waterfall), §14 Phase 4 tickets T-19–T-25.

## Global Constraints

- Package manager `pnpm`; Node `22.x` target.
- TypeScript strict, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true` (type-only imports use `import type`).
- Relative imports throughout (no path aliases configured in this repo, despite `tsconfig.json`'s unused `@/*` entry — the Phase 3 final review confirmed the existing convention is relative imports; follow it).
- **The engine boundary is load-bearing:** `src/engine/**` may not import from `src/app/**`, `src/components/**`, `next/*`, or `react`, and this plan never asks you to violate it — every task in this plan imports *from* the engine, never the reverse.
- **Money/percentage values already come out of the engine as final, rounded, display-ready strings.** No component in this plan performs its own rounding or Decimal math on a `SimulationResult` field — `BreakdownLine.amount`, `netProfit`, `marginPct`, etc. are rendered as-is. `Decimal`/`decimal.js` is not a dependency of any file this plan creates.
- **FxBadge non-negotiable rule (spec §6.3 #1):** wherever a converted figure appears, show `1 USD = <rate> <currency> · rate as of <date>` — visible, never a tooltip, never collapsed.
- **DisclaimerBar non-negotiable rule (spec §6.3 #2):** wherever a converted price appears, show *"Final price is confirmed on Uniqbe's invoice, not by this tool."* — `position: sticky` at the viewport bottom.
- Design tokens (spec §9.1): data columns use `ui-monospace, "SF Mono", "JetBrains Mono", monospace` with tabular figures (`font-variant-numeric: tabular-nums`); interface text uses `Inter Variable` or system stack; verdict colors are `#0F766E` (profitable, teal-700), `#B45309` (marginal, amber-700), `#B91C1C` (loss, red-700); surfaces are `#FAFAF9`/`#FFFFFF`; card radius `6px`, input radius `4px`. Color is never the only signal — every verdict and every waterfall segment also carries a text label.
- Accessibility floor (spec §9.1): WCAG AA contrast, visible keyboard focus, `prefers-reduced-motion` respected, full mobile layout.
- Verdict threshold is the committed constant `VERDICT_MARGIN_THRESHOLD_PCT = 12` in `src/engine/verdict.ts` — do not hardcode `12` anywhere in the UI; import the constant if a component needs to display it.
- One ticket per commit, Conventional Commits format.
- Run `pnpm verify` (`typecheck && lint && test`) before considering any task done.
- This repo's line endings are LF; if `pnpm verify`'s lint step reports every file as a Prettier formatting issue, that is a known pre-existing Windows `core.autocrlf` artifact (see the Phase 3 plan's ledger), not a real defect — normalize with `git ls-files -z | grep -zv '\.xlsx$' | xargs -0 sed -i 's/\r$//'` and re-run.

## Deviation from the spec's component library (read before starting Task 1)

Spec §0 lists `"components": "shadcn-ui (radix primitives, copied into repo, not a dependency)"`. shadcn-ui's own scaffolding is an interactive CLI (`npx shadcn init`) that prompts for choices and writes its own config — awkward to script inside a TDD plan and unnecessary for what these seven tickets need (a search combobox, text/number inputs, a select, a toggle, a table, a card, a stacked bar). This plan builds every component directly with semantic HTML + Tailwind utility classes against the design-token table above, with no Radix/shadcn dependency. Nothing here blocks adopting shadcn later — these are plain, replaceable components with no exotic internal API.

## Deviation from a component-testing stack (read before starting Task 1)

`vitest.config.ts` currently has no `jsdom`/`happy-dom` environment and its `include` pattern only matches `tests/**/*.test.ts` (not `.tsx`), and no `@testing-library/react` is installed. Installing a full component-testing stack is not on the Phase 4 ticket list and is exactly the kind of scope creep YAGNI warns against for tickets that are really about wiring, not novel logic. Instead, this plan extracts every piece of non-trivial *logic* a component needs into a plain, exported function in `src/lib/*.ts` and gives each one real Vitest unit tests (`tests/lib/*.test.ts`, plain `.ts`, no DOM). Each task's React component is then a thin, mostly-untested wiring layer — verified the way the user's own workflow guidance requires for UI changes: run `pnpm dev` and check the feature in a browser before the task is reported done. Full end-to-end coverage of the rendered page arrives in Phase 6 (T-31, Playwright), which is already in the spec's plan — this phase does not need to duplicate it early.

## URL parameter schema (read before starting Task 3, referenced by Tasks 1 and 3)

Per ADR-006 (`nuqs` binds every input, short param names). This plan fixes the complete mapping now so later tasks agree with each other:

| Param | Field | Type | Default |
|---|---|---|---|
| `m` | `market` | `"UK" \| "AU"` | `"UK"` |
| `p` | `productCode` | `string` | `""` (no product selected) |
| `pl` | `platform` | `"amazon" \| "ebay" \| "shopify" \| "other"` | `"amazon"` |
| `reg` | `taxRegistered` | `boolean` | `false` |
| `sp` | `sellingPriceLocal` | `string` | `""` (no price entered) |
| `sh` | `inboundShippingLocal` | `string` | `"0.00"` |
| `pk` | `packagingLocal` | `string` | `"0.00"` |
| `ad` | `adSpendLocal` | `string` | `"0.00"` |
| `du` | `dutyPct` | `string` | `""` (prefilled from category once a product is picked, not a fixed default) |
| `rf` | `referralFeePct` | `string` | `""` (prefilled from category once a product+platform are picked) |
| `ap` | `amazonPlan` | `"individual" \| "professional"` | `"professional"` |
| `shp` | `shopifyPlan` | `"basic" \| "grow" \| "advanced"` | `"basic"` |

| `et` | `ebayFreeTier` | `boolean` | `false` |

`market` is included now (Phase 5 will add a real AU tab) but this phase renders no market switcher — every calculation this phase performs uses `"UK"` regardless of the `m` param's value, and the header shows a static "UK" label. `usd` and `category` are never URL params — they are looked up from the catalogue via `productCode`.

```typescript
// src/lib/fx-format.ts
const MONTH_ABBREVIATIONS = [
  "Jan", "Feb", "Mar", "Apr", "May", "Jun",
  "Jul", "Aug", "Sep", "Oct", "Nov", "Dec",
];

export function formatFxBadgeText(
  rate: number,
  currency: "GBP" | "AUD",
  asOf: string,
): string {
  const [year, month, day] = asOf.split("-").map(Number);
  const monthAbbreviation = MONTH_ABBREVIATIONS[month - 1];
  return `1 USD = ${rate.toFixed(4)} ${currency} · rate as of ${day} ${monthAbbreviation} ${year}`;
}
```

**Note on the manual date parsing:** `asOf` is a bare `YYYY-MM-DD` string with no time component (Phase 3's `FxRawSnapshot` schema enforces `z.string().date()`). Passing that through `new Date(asOf)` and formatting with `toLocaleDateString` would parse it as UTC midnight and then render it in the *browser's local* timezone — anyone west of UTC would see the previous day. Splitting the string and indexing a fixed month array sidesteps the entire class of bug, the same defensive pattern Phase 3's `computeAgeDays` used for the same reason.

```typescript
// src/lib/search.ts
import Fuse from "fuse.js";
import type { CatalogueItemType } from "./schemas";

const FUSE_OPTIONS = {
  keys: ["search"],
  threshold: 0.3,
  ignoreLocation: true,
};

export function filterProducts(
  items: CatalogueItemType[],
  query: string,
): CatalogueItemType[] {
  const trimmed = query.trim();
  if (!trimmed) {
    return items;
  }
  const fuse = new Fuse(items, FUSE_OPTIONS);
  return fuse.search(trimmed).map((result) => result.item);
}
```

Every `CatalogueItemType` already carries a precomputed lowercase `search` field (brand + name + storage + category label, built by `scripts/build-catalogue.ts` in Phase 1) — this is exactly what Fuse should index, so no per-search string concatenation is needed.

```typescript
// src/components/simulator/ProductPicker.tsx
"use client";

import { useMemo, useState } from "react";
import type { CatalogueItemType } from "../../lib/schemas";
import { filterProducts } from "../../lib/search";

interface ProductPickerProps {
  items: CatalogueItemType[];
  selectedCode: string;
  onSelect: (code: string) => void;
}

export function ProductPicker({ items, selectedCode, onSelect }: ProductPickerProps) {
  const [query, setQuery] = useState("");
  const results = useMemo(() => filterProducts(items, query), [items, query]);
  const selected = items.find((item) => item.code === selectedCode) ?? null;

  return (
    <div className="flex flex-col gap-1">
      <label htmlFor="product-search" className="text-sm font-medium">
        Product
      </label>
      <input
        id="product-search"
        type="text"
        className="rounded border border-neutral-300 px-3 py-2 text-sm"
        placeholder={selected ? selected.name : "Search all products…"}
        value={query}
        onChange={(event) => setQuery(event.target.value)}
      />
      {query.trim() !== "" && (
        <ul className="max-h-64 overflow-y-auto rounded border border-neutral-200 bg-white">
          {results.length === 0 ? (
            <li className="px-3 py-2 text-sm text-neutral-500">No products match &ldquo;{query}&rdquo;.</li>
          ) : (
            results.map((item) => (
              <li key={item.code}>
                <button
                  type="button"
                  className="w-full px-3 py-2 text-left text-sm hover:bg-neutral-100"
                  onClick={() => {
                    onSelect(item.code);
                    setQuery("");
                  }}
                >
                  {item.brand} {item.name}
                </button>
              </li>
            ))
          )}
        </ul>
      )}
    </div>
  );
}
```

```typescript
// src/lib/url-state.ts
import {
  parseAsBoolean,
  parseAsString,
  parseAsStringEnum,
} from "nuqs";
import type { SimulationInput } from "../engine/types";

export type ScenarioParams = Omit<SimulationInput, "usd" | "category">;

export const scenarioParsers = {
  m: parseAsStringEnum(["UK", "AU"] as const).withDefault("UK"),
  p: parseAsString.withDefault(""),
  pl: parseAsStringEnum(["amazon", "ebay", "shopify", "other"] as const).withDefault("amazon"),
  reg: parseAsBoolean.withDefault(false),
  sp: parseAsString.withDefault(""),
  sh: parseAsString.withDefault("0.00"),
  pk: parseAsString.withDefault("0.00"),
  ad: parseAsString.withDefault("0.00"),
  du: parseAsString.withDefault(""),
  rf: parseAsString.withDefault(""),
  ap: parseAsStringEnum(["individual", "professional"] as const).withDefault("professional"),
  shp: parseAsStringEnum(["basic", "grow", "advanced"] as const).withDefault("basic"),
  abn: parseAsBoolean.withDefault(false),
  et: parseAsBoolean.withDefault(false),
};

export const DEFAULT_SCENARIO: ScenarioParams = {
  market: "UK",
  productCode: "",
  platform: "amazon",
  taxRegistered: false,
  sellingPriceLocal: "",
  inboundShippingLocal: "0.00",
  packagingLocal: "0.00",
  adSpendLocal: "0.00",
  dutyPct: "",
  referralFeePct: "",
  amazonPlan: "professional",
  shopifyPlan: "basic",
  shopifyHasAbn: false,
  ebayFreeTier: false,
};

export function decodeScenario(searchParams: URLSearchParams): ScenarioParams {
  return {
    market: scenarioParsers.m.parseServerSide(searchParams.get("m") ?? undefined),
    productCode: scenarioParsers.p.parseServerSide(searchParams.get("p") ?? undefined),
    platform: scenarioParsers.pl.parseServerSide(searchParams.get("pl") ?? undefined),
    taxRegistered: scenarioParsers.reg.parseServerSide(searchParams.get("reg") ?? undefined),
    sellingPriceLocal: scenarioParsers.sp.parseServerSide(searchParams.get("sp") ?? undefined),
    inboundShippingLocal: scenarioParsers.sh.parseServerSide(searchParams.get("sh") ?? undefined),
    packagingLocal: scenarioParsers.pk.parseServerSide(searchParams.get("pk") ?? undefined),
    adSpendLocal: scenarioParsers.ad.parseServerSide(searchParams.get("ad") ?? undefined),
    dutyPct: scenarioParsers.du.parseServerSide(searchParams.get("du") ?? undefined),
    referralFeePct: scenarioParsers.rf.parseServerSide(searchParams.get("rf") ?? undefined),
    amazonPlan: scenarioParsers.ap.parseServerSide(searchParams.get("ap") ?? undefined),
    shopifyPlan: scenarioParsers.shp.parseServerSide(searchParams.get("shp") ?? undefined),
    shopifyHasAbn: scenarioParsers.abn.parseServerSide(searchParams.get("abn") ?? undefined),
    ebayFreeTier: scenarioParsers.et.parseServerSide(searchParams.get("et") ?? undefined),
  };
}

export function encodeScenario(scenario: ScenarioParams): URLSearchParams {
  const params = new URLSearchParams();
  params.set("m", scenarioParsers.m.serialize(scenario.market));
  params.set("p", scenarioParsers.p.serialize(scenario.productCode));
  params.set("pl", scenarioParsers.pl.serialize(scenario.platform));
  params.set("reg", scenarioParsers.reg.serialize(scenario.taxRegistered));
  params.set("sp", scenarioParsers.sp.serialize(scenario.sellingPriceLocal));
  params.set("sh", scenarioParsers.sh.serialize(scenario.inboundShippingLocal));
  params.set("pk", scenarioParsers.pk.serialize(scenario.packagingLocal));
  params.set("ad", scenarioParsers.ad.serialize(scenario.adSpendLocal));
  params.set("du", scenarioParsers.du.serialize(scenario.dutyPct));
  params.set("rf", scenarioParsers.rf.serialize(scenario.referralFeePct));
  params.set("ap", scenarioParsers.ap.serialize(scenario.amazonPlan));
  params.set("shp", scenarioParsers.shp.serialize(scenario.shopifyPlan));
  params.set("abn", scenarioParsers.abn.serialize(scenario.shopifyHasAbn));
  params.set("et", scenarioParsers.et.serialize(scenario.ebayFreeTier));
  return params;
}
```

**Note on `parseServerSide`/`serialize`:** these are plain functions on every `nuqs` parser object, independent of React — this is what makes `decodeScenario`/`encodeScenario` unit-testable in Node without mounting anything. The React-facing hook (`useQueryStates(scenarioParsers)`, wired into `SimulatorShell` in Step 5) is a thin layer over the same parsers; this test file never touches it.

```typescript
// src/components/simulator/SimulatorShell.tsx — full replacement of the component body from Task 2
"use client";

import { useQueryStates } from "nuqs";
import type { CatalogueType, MarketRulesType, FxSnapshotType } from "../../lib/schemas";
import { scenarioParsers } from "../../lib/url-state";
import { calculate } from "../../engine";
import type { FxInput } from "../../engine/types";
import { FxBadge } from "./FxBadge";
import { DisclaimerBar } from "./DisclaimerBar";
import { ProductPicker } from "./ProductPicker";
import { InputPanel } from "./InputPanel";

interface SimulatorShellProps {
  catalogue: CatalogueType;
  rules: MarketRulesType;
  fx: FxSnapshotType;
}

export function SimulatorShell({ catalogue, rules, fx }: SimulatorShellProps) {
  const [scenario, setScenario] = useQueryStates(scenarioParsers);
  const market = "UK" as const;
  const currency = market === "UK" ? "GBP" : "AUD";
  const rate = market === "UK" ? fx.rates.GBP : fx.rates.AUD;

  const selectedItem = catalogue.items.find((item) => item.code === scenario.productCode) ?? null;

  function selectProduct(code: string) {
    const item = catalogue.items.find((i) => i.code === code);
    if (!item) return;
    setScenario({
      ...scenario,
      productCode: code,
      dutyPct: String(rules.UK.dutyPctByCategory[item.category]),
      referralFeePct: String(
        rules.UK.platforms[scenario.platform].referralFeePctByCategory[item.category],
      ),
    });
  }

  const fxInput: FxInput = { rate: String(rate), asOf: fx.asOf, degraded: fx.degraded };
  const sellingPriceValid = Number(scenario.sellingPriceLocal) > 0;
  const result =
    selectedItem && sellingPriceValid
      ? calculate(
          { ...scenario, market: "UK", usd: selectedItem.usd, category: selectedItem.category },
          fxInput,
          rules,
        )
      : null;

  return (
    <div className="flex min-h-screen flex-col bg-[#FAFAF9]">
      <header className="border-b border-neutral-200 bg-white px-4 py-3">
        <div className="flex items-center justify-between">
          <h1 className="text-lg font-semibold">Uniqbe Price Simulator</h1>
          <span className="rounded-full border border-neutral-300 px-3 py-1 text-sm">UK</span>
        </div>
        <FxBadge rate={rate} currency={currency} asOf={fx.asOf} />
      </header>

      <main className="flex flex-1 flex-col gap-6 px-4 py-6 md:flex-row">
        <section className="flex flex-col gap-4 md:w-80">
          <ProductPicker items={catalogue.items} selectedCode={scenario.productCode} onSelect={selectProduct} />
          <InputPanel
            scenario={scenario}
            onChange={setScenario}
            rules={rules}
            category={selectedItem?.category ?? null}
          />
        </section>

        <section className="flex-1">
          {result ? (
            <p className="text-sm text-neutral-600">
              Net profit: {result.netProfit} · Margin: {result.marginPct}% · Verdict: {result.verdict}
            </p>
          ) : (
            <p className="text-neutral-500">
              Select a product and enter a selling price to see your profit breakdown.
            </p>
          )}
        </section>
      </main>

      <DisclaimerBar />
    </div>
  );
}
```

```typescript
// src/components/simulator/BreakdownTable.tsx
import type { BreakdownLine } from "../../engine/types";
import { alignedAmount } from "../../lib/breakdown-format";

const AMOUNT_COLUMN_WIDTH = 12;

interface BreakdownTableProps {
  lines: BreakdownLine[];
  netProfit: string;
  currency: "GBP" | "AUD";
}

const CURRENCY_SYMBOL: Record<"GBP" | "AUD", string> = { GBP: "£", AUD: "A$" };

export function BreakdownTable({ lines, netProfit, currency }: BreakdownTableProps) {
  const symbol = CURRENCY_SYMBOL[currency];
  return (
    <table className="w-full border-collapse font-mono text-sm [font-variant-numeric:tabular-nums]">
      <tbody>
        {lines.map((line) => (
          <tr key={line.label} data-testid={`breakdown-row-${line.label}`}>
            <td className="py-1 pr-4 text-neutral-700">{line.label}</td>
            <td className="py-1 text-right">
              {symbol}
              {alignedAmount(line.amount, AMOUNT_COLUMN_WIDTH)}
            </td>
          </tr>
        ))}
        <tr className="border-t border-neutral-300 font-semibold">
          <td className="py-2 pr-4">Net profit</td>
          <td className="py-2 text-right">
            {symbol}
            {alignedAmount(netProfit, AMOUNT_COLUMN_WIDTH)}
          </td>
        </tr>
      </tbody>
    </table>
  );
}
```

```typescript
// src/lib/waterfall.ts
import type { BreakdownLine } from "../engine/types";

export interface WaterfallSegment {
  label: string;
  widthPct: number;
  negative: boolean;
}

const GROSS_SELLING_PRICE_LABEL = "Gross selling price";

export function computeWaterfallSegments(
  lines: BreakdownLine[],
  netProfit: string,
): WaterfallSegment[] {
  const grossLine = lines.find((line) => line.label === GROSS_SELLING_PRICE_LABEL);
  const gross = Math.abs(Number(grossLine?.amount ?? "0"));

  const deductionSegments = lines
    .filter((line) => line.label !== GROSS_SELLING_PRICE_LABEL)
    .map((line) => {
      const value = Number(line.amount);
      return {
        label: line.label,
        widthPct: gross === 0 ? 0 : (Math.abs(value) / gross) * 100,
        negative: value < 0,
      };
    });

  const profitValue = Number(netProfit);
  const profitSegment: WaterfallSegment = {
    label: "Net profit",
    widthPct: gross === 0 ? 0 : (Math.abs(profitValue) / gross) * 100,
    negative: profitValue < 0,
  };

  return [...deductionSegments, profitSegment];
}
```

```typescript
  disabled: boolean;

const DEFAULT_TARGET_MARGIN_PCT = 20;

export function PriceSuggestion({ input, fx, rules, onApply, disabled }: PriceSuggestionProps) {
  const [targetMarginPct, setTargetMarginPct] = useState(DEFAULT_TARGET_MARGIN_PCT);
  const [result, setResult] = useState<{ price: string; steps: number } | null>(null);
  const [hasSuggested, setHasSuggested] = useState(false);

      <label htmlFor="target-margin" className="text-sm font-medium">

          id="target-margin"
          type="number"
          className="w-20 rounded border border-neutral-300 px-2 py-1 text-sm"
          value={targetMarginPct}
          min={0}
          max={99}
          onChange={(event) => {
            setTargetMarginPct(Number(event.target.value));
            setHasSuggested(false);
            setResult(null);
          }}
        />
        <span className="text-sm text-neutral-600">% margin</span>
        <button
          type="button"
          className="rounded bg-neutral-900 px-3 py-1 text-sm text-white disabled:opacity-40"
          disabled={disabled}
          onClick={handleSuggest}
        >
          Suggest
        </button>
      </div>
      {result && (
        <p className="text-sm text-neutral-700">
          Suggested price: <span className="font-mono">{result.price}</span>{" "}
          <button type="button" className="underline" onClick={() => onApply(result.price)}>
            Apply
          </button>
        </p>
      )}
      {result === null && hasSuggested && (
        <p className="text-sm text-neutral-500">
          A {targetMarginPct}% margin isn&rsquo;t reachable at any selling price for this setup —

}
```
