# Phase 5 (Australia) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the already-built, already-tested Australian market support in the UI: a market tab switcher, a de-minimis threshold banner, and the eBay free-tier / Shopify ABN toggles — so a partner can run the exact same simulator against AU instead of UK.

**Architecture:** No engine changes. `src/engine/**` (markets, warnings, platform fees) already fully implements AU behavior via `input.market: "AU"`, `input.ebayFreeTier`, `input.shopifyHasAbn` — confirmed by reading `src/engine/markets/au.ts`, `src/engine/warnings.ts`, `src/engine/index.ts`, and golden fixture GF-08. `src/lib/url-state.ts` already round-trips `market`/`ebayFreeTier`/`shopifyHasAbn` through the URL. The gap is entirely in `SimulatorShell.tsx` (which hardcodes `const market = "UK" as const`, discarding `scenario.market` at 6 call sites) and `InputPanel.tsx` (which never renders controls for the two AU-only toggles). This plan fixes the hardcode, adds two new thin presentational components (`MarketTabs`, `ThresholdBanner`), and extends `InputPanel` with two conditional checkboxes — extracting one small shared pure-function module (`scenario-defaults.ts`) along the way to stop the market-dependent duty/referral-fee defaults from being re-derived three different ways across two files.

**Tech Stack:** Same as Phase 4 — Next.js 15 App Router, React 19, `nuqs` (already installed), Tailwind CSS 4, Vitest 2 (pure-logic tests only, per Phase 4's established no-jsdom convention).

**Spec:** `PROJECT_SPEC.md` (repo root) — §14 Phase 5 tickets T-26/T-27/T-28; §2.6/§2.8 (AU de-minimis comparand, goods-only, authoritative); §7.2/§7.3/§7.6 (calculation steps, platform fees, warnings); §9.2/§9.3 (market-tab wireframe, ThresholdBanner exact copy); §6.3 (FxBadge/DisclaimerBar non-negotiable rules, already satisfied, unaffected by this plan).

## Global Constraints

- Package manager `pnpm`; Node `22.x` target.
- TypeScript strict, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true` (type-only imports use `import type`).
- Relative imports throughout (no path aliases).
- **The engine boundary is load-bearing and this plan is engine-read-only:** `src/engine/**` needs zero changes for T-26/T-27/T-28 — every AU behavior this plan surfaces (market switch, threshold, eBay free tier, Shopify ABN warning) is already implemented and tested. Every task in this plan imports *from* the engine, never the reverse.
- Money/percentage values from the engine are rendered as-is — no component performs its own rounding or Decimal math on a `SimulationResult` field.
- **AU de-minimis rule — goods-only, do not reimplement it:** `SimulationResult.auAboveThreshold: boolean | null` already carries the correct, fixture-verified answer (`null` for UK, `true`/`false` for AU, computed by `src/engine/markets/au.ts`'s goods-only comparand). `ThresholdBanner` (Task 2) reads this field directly and must never recompute the A$1,000 comparison itself. **Known spec-internal contradiction, already resolved:** `PROJECT_SPEC.md`'s own T-27 acceptance text, §7.2 step 3, `AGENTS.md` invariant 5a, and its §11.4 manual-QA checklist all contain stale "goods+freight" wording left over from a reverted v1.1 draft (see the spec's own changelog and `market-rules.json`'s `_meta.changeLog`). The spec itself states the resolution rule: "if prose and fixtures ever disagree, the fixtures win" (§7) — and fixtures GF-06a/b/c prove goods-only (freight raised 25× in GF-06c does not flip the threshold). This plan follows the fixtures; freight fields in `InputPanel` do not and should not affect the banner.
- **eBay free-tier default: OFF**, matching the existing `DEFAULT_SCENARIO.ebayFreeTier = false`. This resolves the spec's own open question (§15 #6) toward the conservative choice — defaulting it on would flatter AU eBay margins by ~13 points for anyone who has outgrown the tier.
- **Known, accepted, pre-existing engine-layer gap — do not fix as part of this plan:** the A$1,000 threshold and the "goods" comparand are hardcoded constants independently duplicated in `src/engine/markets/au.ts` and `src/engine/warnings.ts`, not read from `market-rules.json` at runtime (documented in that file's own `AU.deMinimisComparandNote`).
```typescript
// src/lib/scenario-defaults.ts
import type { MarketRulesType, CategorySlugType } from "./schemas";
import type { Market, Platform } from "../engine/types";

export function deriveDutyPctDefault(
  rules: MarketRulesType,
  market: Market,
  category: CategorySlugType,
): string {
  return String(rules[market].dutyPctByCategory[category]);
}

export function deriveReferralFeeDefault(
  rules: MarketRulesType,
  market: Market,
  platform: Platform,
  category: CategorySlugType,
): string {
  const platformFees = rules[market].platforms[platform];
  return "referralFeePctByCategory" in platformFees
    ? String(platformFees.referralFeePctByCategory[category])
    : String(platformFees.referralFeePctDefault);
}
```

This consolidates three separate, slightly-inconsistent re-derivations of the same two values that currently exist across `SimulatorShell.tsx` (`selectProduct`) and `InputPanel.tsx` (`onPlatformChange`) — both are rewritten to call these functions in Steps 6–7 below, and this is also what makes `selectProduct`/`onPlatformChange` market-aware instead of UK-only.
